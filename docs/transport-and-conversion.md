# 传输与转换方案

> 状态：草案 / 决策记录 ｜ 更新：2026-11-06
>
> 本文回答两个反复被问到的问题：**书怎么进 Kindle**、**为什么一定要 calibre**。
> 已实现的部分标「已实现」，还只是提案的标「提案」。

## 0. 一个绕不开的硬约束

Kindle 原生**不监听任何端口**：没有 SMB、没有 FTP、没有 HTTP 服务。所以「电脑主动把文件推进 Kindle」在未越狱设备上不成立，方向只能是 **Kindle 主动来拉**。

这条约束决定了下面三种后端的取舍。

## 1. 三种传输后端

### 1.1 局域网推送（已实现）

Mac 上起一个只读 HTTP 服务（默认 `:8180`），Kindle 用自带「体验版网页浏览器」打开地址，点书名下载。

- 入口：工作台 → **传送**
- 代码：`src/host/push.ts`
- 优点：不需要越狱、不需要线、跨平台
- 缺点：**必须在 Kindle 上手动操作**（打开浏览器 → 点书名）；Kindle 浏览器对中文文件名兼容差，所以下载名用 ASCII slug，扩展名统一 `.azw` / `.mobi`

### 1.2 越狱 SFTP（已实现）

Kindle 越狱并开启 SSH（USBNetwork / KUAL）后，Mac 直接 SFTP 读写 `/mnt/us/documents`。

- 入口：工作台 → **Kindle**
- 代码：`src/host/sftp.ts`
- 能力：列出、上传、删除、回传设备上的书
- 优点：Kindle 端零操作，Mac 上选完即完成
- 缺点：需要越狱；Kindle 的 dropbear 很老，需要放宽 SSH 算法（已处理）

### 1.3 USB 直连（提案，未实现）

插数据线后 Kindle 挂载为 U 盘，把文件拷进 `documents/`。

- 挂载点（待验证）：
  - macOS：`/Volumes/Kindle/documents`
  - Linux：`/media/$USER/Kindle/documents`
  - Windows：`<盘符>:\documents`
- 计划能力：检测挂载 → 列出设备上的书 → 上传选中 / 删除
- 优点：零操作、不依赖越狱、传输最稳（不受 Wi-Fi 影响）
- 缺点：需要插线；部分新机型走 MTP，macOS 上可能不挂载为普通卷；Kindle 处于 USB 模式时设备端书库不可用

实现位置建议：新增 `src/host/usb.ts`，路由 `/usb/*`，工作台增加「USB」视图或并入「Kindle」页做第三种连接方式。

### 1.4 对比

| | 局域网推送 | 越狱 SFTP | USB 直连 |
|---|---|---|---|
| 需要越狱 | 否 | 是 | 否 |
| Kindle 端操作 | 打开浏览器点下载 | 无 | 无 |
| 需要线 | 否 | 否 | 是 |
| 能读取/删除设备书 | 否 | 是 | 是（若挂载可写） |
| 实现状态 | 已实现 | 已实现 | 提案 |

## 2. 为什么 Kindle 端要手动下载

推送模式下，Mac 只负责「把书摆出来」，点击动作必须发生在 Kindle 上：

1. Kindle 没有可被连接的入口（见 §0）
2. 浏览器下载是设备侧行为，Mac 无法代劳
3. Kindle 浏览器的多文件自动下载会被拦，也不适合做「一键全下」

能优化的只有「少点几下」：

- 推送端口固定，Mac 的局域网 IP 不变时地址长期有效
- Kindle 浏览器里把推送页存成书签，之后一步打开
- 下载页保持极简：大字号、单列、点书名即下载

## 3. 格式转换与 calibre 依赖

### 3.1 现状

| 功能 | 依赖 calibre |
|---|---|
| 书库扫描、标题/作者/封面 | 否（EPUB 用 fflate 直解 OPF） |
| 局域网推送 | 否 |
| SFTP 管理 | 否 |
| **EPUB/PDF/MOBI → MOBI/AZW3** | **是**（`ebook-convert`） |

`ebook-meta` 只在「非 EPUB 补充元数据」的接口里用，主流程不调用。

没装 calibre 时插件照常加载，只是转换按钮报「calibre 不可用」。也就是说 calibre 是**可选依赖**，不是启动前提。

### 3.2 去掉 calibre 的三条路

| 方案 | 可行性 | 代价 |
|---|---|---|
| 保持现状（系统安装 calibre） | 高 | 用户需自行安装，路径可配 |
| 内置便携版 calibre | 中 | 首次下载/解压 ~200MB+，需要平台分包与校验 |
| 纯 JS 转换（EPUB → MOBI/AZW3） | 低 | 没有可靠实现；排版、目录、字体嵌入都要自研，PDF 基本做不了 |

### 3.3 建议

- 短期：保持「可选依赖」，在设置页把 calibre 状态显示清楚，不阻塞其它功能
- 中期：若要在多台机器上零配置使用，做**内置便携版**（按平台下载 + sha256 校验），而不是重写转换器
- 不推荐纯 JS 重写：投入大、质量不可控，且 PDF 路线走不通

## 4. 格式选择

- 默认 **MOBI**：兼容性最好，Kindle 浏览器下载白名单也友好
- **AZW3** 可选：KF8 排版更好；下载时对外呈现为 `.azw`（字节不变），绕过浏览器扩展名白名单
- 转换参数：MOBI 用 `--mobi-file-type new`，AZW3 用 `--output-profile kindle_pw3`
